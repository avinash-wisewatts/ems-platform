# Portal user provisioning — initial EMS administrator

Status: CURRENT (procedure implemented 2026-11-03, not yet run on staging or production) · Owner: Engineering
Related: [ADR-023 Amendment 2](../00-governance/decisions/ADR-023-customer-staff-separation.md), [../05-applications/admin-portal/README.md](../05-applications/admin-portal/README.md)

## What it does

`python -m src.provision_portal_admin` (`app/src/provision_portal_admin.py`)
creates one portal account — by default `admin_user`, role **ADMIN**, scope
**GLOBAL** (the highest-privilege role; WiseWatts-staff reach) — through
`admin.create_managed_portal_user`, the same controlled, audited function the
Administration App's Users page uses. The audit row (`admin.portal_user_audit`,
`USER_CREATED`) names the existing administrator given as `--actor-username`.

Guarantees:

- An existing account with that username is **never** modified, re-activated
  or given a new password — the command stops (exit 3) and changes nothing.
- The password is generated by the command (CSPRNG), stored only as an
  Argon2id hash, never logged and never passed on a command line.
- It is handed over once: to a **new** file (`--password-file`, created
  exclusively, owner read/write only), or — without that option — printed to
  an interactive terminal only (refused on a pipe or log).
- The file is prepared before the account is created, so an account is never
  left with a password nobody received.

Requires migration 315 only for the follow-up password change (the creation
itself uses a pre-existing function).

## Procedure (each environment needs explicit approval — it creates a live account)

1. Read-only pre-check: `admin_user` absent; at least one active ADMIN/GLOBAL
   administrator to act as `--actor-username`.
2. In the admin-portal container (it has the application's database
   settings), as an operator:

   ```sh
   docker exec -it ems-admin-portal \
     python -m src.provision_portal_admin \
       --username admin_user \
       --display-name "EMS Administrator" \
       --email <administrator e-mail> \
       --actor-username <existing active GLOBAL administrator>
   ```

   `-it` gives an interactive terminal, so the password is printed once to it.
   To use a file instead, add `--password-file /tmp/admin_user_password.txt`,
   then copy it out (`docker cp`), read it, and delete both copies.
3. Sign in at the **Administration App** `/login` (the account is staff, so
   `EMS_ADMIN_STAFF_ONLY` does not affect it), open `/app/`, then
   Admin → Users → your own account → **Change my password**. Where the
   staff console is deployed (ADR-023 Amendment 3), `/admin/users` on the
   Administration App is the same screen and remains after stage 4.

There is no forced change at first sign-in (the portal does not support it);
step 3 is the replacement. If the password is lost, another GLOBAL
administrator resets it in Admin → Users (a user cannot reset their own).

**Session limitation (ADR-023 R2, issue #172).** A password reset does not end
sessions that are already signed in. If a password may have been exposed,
deactivate the account first; that stops its data access at once. Then reset
the password and reactivate. Rotating the Administration App session secret is
the only way to end every session.
