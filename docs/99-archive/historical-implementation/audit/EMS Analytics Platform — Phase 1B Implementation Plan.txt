1. Executive Summary

Phase 1A proved a repeatable pattern: declare an already-correct object canonical, add a disposable-database behavioral contract test, migrate consumers only if they aren't already on it. Applying "architecture-driven, not generic cleanup" discipline, the next workstream the source documents themselves designate as highest-priority — restated verbatim in the Phase 1 Semantic Model ("This is the highest-priority semantic contract") — is Energy Consumption. Unlike connectivity, the canonical energy-consumption object (analytics.energy_consumption_{1min,5min,15min,hourly,daily}) is not yet consumed by anything (confirmed by its own repository test, test_reporting_contract_is_not_yet_exposed_to_consumers) — so Phase 1B cannot simply repeat "declare + test, no migration needed." This asymmetry is the central finding of this plan and the reason Phase 1B is scoped narrower than a full consolidation: prove the canonical calculation with a contract test; do not migrate any consumer yet. Consumer migration is deliberately deferred to a later phase, once resolution-routing (a separate, already-identified gap) is also addressed — exactly mirroring how the source documents sequenced this work.

4. Semantic Model

Already fully specified in the Phase 1 Semantic Model (§4) and re-verified in the Final Reconciliation (§12, reconciliation table). Restated only where it governs scope: energy consumption is a register delta, classified once at native resolution (1m or 5m, mutually exclusive by site capture policy) via analytics.classify_energy_register_delta(), rolled up additively at 15m (from native), then at hourly and daily (both from 15m only, never from each other or from raw registers), with site-local timezone correctness at hourly/daily. This is not being redefined here — Phase 1B's job is to prove this model against real fixture data, exactly as Phase 1A proved connectivity's state machine.

7. Proposed Changes

Required: one new disposable-database contract test (scripts/test/assert_energy_consumption_semantic_contract.sql + .sh, following the exact Phase 1A convention), wired into run_integration_environment.sh. It should assert, using fixture data (no staging fixtures — local disposable DB only):
- A native-resolution register delta computes the correct GOOD/GAP/RESET/ROLLOVER classification for representative scenarios (mirrors the already-existing classify_energy_register_delta unit coverage in assert_energy_register_semantics.sh, but exercised through the persisted table's refresh path, which is not currently covered end-to-end).
- A 15-minute rollup correctly sums only valid native intervals and counts invalid/gap/reset/rollover intervals separately.
- Hourly rolls up from 15-minute only; daily rolls up from 15-minute only (not hourly) — provable by constructing a case where hourly-then-daily and 15min-then-daily would disagree (a UTC-hour crossing a site-local midnight) and asserting the daily figure matches the 15-minute-derived expectation.
- Site-local timezone correctness at the daily tier for a non-UTC site.

Optional: none identified as clearly beneficial without also doing consumer migration (which is explicitly deferred).

Must NOT be changed: any consumer object (v_energy_consumption_15min, get_grafana_asset_energy_intervals(), Analytics Explorer, any dashboard), any migration/DDL for the energy-consumption tables themselves (they are correct as-is), the job-schedule drift, the connectivity threshold-fallback inconsistency, demand/load-profile/energy-balance objects, ingestion/live-telemetry/Telegraf, CI workflow YAML (only the existing run_integration_environment.sh gains a new invocation line, same pattern as Phase 1A).
