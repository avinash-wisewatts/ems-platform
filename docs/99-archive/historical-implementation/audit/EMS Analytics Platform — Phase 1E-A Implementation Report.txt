D. TEST SCENARIOS
===============================================================================

scripts/test/assert_energy_consumption_per_flow_quality_contract.sql —
fixture: two organizations/sites (Asia/Kolkata), two devices. Device A
carries seven native 1-minute intervals (one per 15-minute bucket, 2026-
01-01 09:00 through 10:30 UTC), each independently classified via a real
call to analytics.classify_energy_register_delta() for both import and
export, covering all seven required combinations: GOOD/GOOD, GAP/GOOD,
GOOD/GAP, RESET/GOOD, GOOD/RESET, ROLLOVER/GOOD, GOOD/ROLLOVER. Device B
(a different organization) carries one GOOD/GOOD interval only, used
purely as a tenant-isolation control.

Assertions (all against the real, unmodified refresh functions and real
persisted tables — no fixture value copied from the implementation's own
output):
    1. Fixture sanity: classifier actually produced the seven distinct
       import/export code combinations depended on.
    2. 15-minute persistence: exact per-flow arrays (import/export gap,
       reset, rollover interval counts) across all seven buckets, exact
       combined-counter arrays (proving compatibility unchanged), exact
       import/export_consumption_kwh arrays (proving GAP/ROLLOVER
       contribute and RESET is excluded, per Phase 1B, unaffected by this
       migration).
    3. Tenant isolation at the 15-minute tier: device B's row shows the
       correct organization_id and zero per-flow quality counters (no
       cross-tenant contamination in the write path).
    4. Hourly aggregation: two hourly buckets (09:00 covering GOOD/GOOD,
       GAP/GOOD, GOOD/GAP, RESET/GOOD; 10:00 covering GOOD/RESET,
       ROLLOVER/GOOD, GOOD/ROLLOVER), each asserted for exact per-flow
       sums and exact import/export_consumption_kwh sums.
    5. Daily aggregation: one row for device A with per-flow sums equal
       to the total across all seven buckets (1 each for gap/reset/
       rollover per flow), combined counters (2/2/2/2), consumption_kwh
       (0.120/0.120), source_interval_count (7), and site_timezone
       (Asia/Kolkata) — confirming site-local bucketing is unaffected.
    6. Tenant isolation at the daily tier: device B's daily row, same
       check as (3).

One fixture bug was found and corrected during local validation (not an
implementation defect): the test's expected hourly kWh values had import
and export sums transposed for both hourly buckets (0.040/0.040 and
0.080/0.080 were written where 0.040/0.050 and 0.080/0.070 were correct,
since the RESET bucket differs by flow between the two hours). The
database's actual output was correct on the first run; only the test's
own expected-value arithmetic was wrong. Corrected and re-verified.
